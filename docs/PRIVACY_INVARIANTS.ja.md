# プライバシー不変条件

*[English](./PRIVACY_INVARIANTS.md) · 日本語*

これは Copaky が主張している**構造的な**性質です — 元になっている完全な一覧（「このアプリが主
張していること（攻撃していただきたい対象）」）は [SECURITY.md](../SECURITY.md) にあります。プル
リクエストは、明示的でレビュー済みの理由なしにこれらを壊してはいけません。これは
[PR テンプレート](../.github/PULL_REQUEST_TEMPLATE.md) から参照されるチェックリストであり、機械
的に検証できる範囲は [PR ゲート](../.github/workflows/pr-gate.yml) とローカルのテストスイートで
担保されます。

各項目について：意味・現在どう検証しているか・その領域に触れる PR が何を書くべきか、を示しま
す。

## 1. キーボード拡張は通信を一切行わない

**意味。** `Keyboard/` およびその拡張の共有コードは、いかなるネットワーク要求も行いません。テ
レメトリ・解析・遠隔設定・アカウントは一切ありません。App Store のプライバシーラベル
（「データは収集されません」）の根拠であり、譲れない前提です。

**検証方法。** `scripts/audit_network_calls.py`（アドバイザリなオフライン監査、
`scripts/ci-local.sh` のフル実行に含まれる）が、拡張ターゲットから到達可能なネットワーク API
（`URLSession`、`Network.framework`、生ソケット）を走査します。

**PR が書くべきこと。** `Keyboard/` 付近に依存関係やコードパスを追加する場合、ネットワークに到
達し得るかどうかと、監査スクリプトがなぜクリーンなままなのかを明示してください。

## 2. アプリ全体でテレメトリ・解析なし

**意味。** アプリにも拡張にも、クラッシュレポーター・利用状況解析 SDK・A/B テストの仕組みはあり
ません。存在するテレメトリは、Apple 自身が TestFlight（App Store Connect）経由で収集するものだ
けで、それは Apple のインフラであり Copaky のものではありません。

**検証方法。** 上記と同じ監査をアプリターゲットにも拡張し、手動の依存関係レビューも行います —
`Package.swift` / Xcode プロジェクトのパッケージグラフに解析 SDK が含まれていないこと。

**PR が書くべきこと。** 新しいサードパーティ依存関係は、何をするものか、ネットワーク通信を行わ
ずデータ収集も行わないことを確認してください。

## 3. クリップボードの値を読むのは明示的なユーザー操作時のみ

**意味。** キーボードはシステムのペーストボード「が変化したこと」（変更カウンターというメタデ
ータ）は検知してよいですが、その「内容」を読むのはユーザーが取り込みボタンをタップしたときだけ
です。そのユーザー操作なしにクリップボードの内容を読むコードパスは、機能ではなく脆弱性です — こ
れは SECURITY.md でも「攻撃していただきたい5つの性質」の一つとして挙げられています。

**検証方法。** `ClipboardHistoryManagerTests`（`scripts/ci-local.sh` が実行する `AzooKeyCore` ス
イートの一部）と、[PR テンプレート](../.github/PULL_REQUEST_TEMPLATE.md) のチェック項目「明示的
なユーザー操作なしにクリップボードの値を読んでいないこと」。

**PR が書くべきこと。** クリップボード取り込みのコードに触れる場合、読み取りをゲートしているユ
ーザー操作は何か、それをどのテストがカバーしているかを明記してください。

## 4. App Group コンテナの外には何も書き込まない

**意味。** クリップボード履歴やその他の永続化状態は、アプリと拡張が共有できる App Group コンテ
ナの中だけに存在し、それ以外の場所（任意のサンドボックスパスへの書き込みや、共有すべきもの・
予期しない形で再インストール後も残ってしまう `UserDefaults.standard` の使用）には存在しません。

**検証方法。** 現時点では自動チェックはなく、コードレビューで確認します。新しい永続化値を追加
する PR は、どのコンテナに置かれるかを明記してください。

**PR が書くべきこと。** 新しい永続化値ごとに：どのコンテナに置かれるか、何が削除のトリガーにな
るか（サイズ上限・保持期間があれば）、再インストール後も残るか（機微な内容であれば残るべきでは
ありません）。

## 5. 入力内容をログに残さない

**意味。** **Release ビルドでは**、ユーザーが入力した内容に類する情報 — 単語・変換候補・クリップボードのテキスト — は、
`os_log`・`print`・クラッシュログなど、端末外に出たりアプリ自身のストレージを超えて残ったりし得
るいかなるシンクにも到達しません。診断ログはイベントが「起きたこと」は記録してよいですが（例：
「自動修正が発火した」）、その「内容」は決して記録しません。唯一の例外は、実機テスト手順のための `#if DEBUG` 限定の自動修正ログ（入力語と候補を記録）で、Release / TestFlight ビルドには含まれず、PR でその範囲を広げてはなりません。

**検証方法。** 現時点ではコードレビューで確認します。実機テスト中に導入した DEBUG 限定の自動修
正ログはビルド構成でスコープされ Release からは除外されますが、DEBUG 内であっても、誤修正率の
デバッグに必要な範囲を超えて入力内容を特定できるものであってはなりません。

**PR が書くべきこと。** 入力・変換・クリップボード付近の新しいログ行は、実際に入力／コピーされ
たテキストを含んでいないこと、および DEBUG 限定かどうかを確認してください。

## 6. セキュア入力欄は対象外

**意味。** パスワード欄（`UITextInputTraits.isSecureTextEntry`）に入力された内容は、クリップボ
ード履歴に取り込まれることも、ログに残ることもありません。

**検証方法。** `ClipboardHistoryManagerTests` にセキュア入力欄のガードケースが含まれ、実機ラウ
ンドでも手動で確認します。

**PR が書くべきこと。** セキュア入力欄の検出方法を変更する場合、ガードのテストが引き続き通るこ
と、変更した経路を引き続きカバーしていることを確認してください。

## 7. ユーザー向け文字列は3言語すべて揃っている

**意味。** 厳密な意味でのセキュリティ不変条件ではありませんが、「気づかないうちに壊れてはいけ
ない」という性質は同じです：`Resources/Localizable.xcstrings` の全てのユーザー向け文字列は、日
本語・英語・イタリア語が揃っている必要があります — 翻訳が空だと、キー名にフォールバックするので
はなく、端末上で空白のキーとして表示されます。

**検証方法。** `scripts/ci-local.sh` の String Catalog lint ステップと、対応する PR テンプレー
トのチェック項目。

**PR が書くべきこと。** 新しいユーザー向け文字列を追加する場合、テストしていた言語だけでなく3
言語すべてが埋まっていることを確認してください。

---

ある変更がこれらのいずれかに触れるかどうか確信が持てない場合は、推測せず PR の説明にその旨を書
いてください — メンテナーは、気づかれない形での退行をレビューするより、質問に答える方を望みま
す。
